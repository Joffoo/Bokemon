# 实验设计：三轨并行（3 个独立实例） vs 单 Agent 一次发散

> 状态：已完成（结论见 docs/adr/0001-oogiri-divergence-single-instance.md）
> 对象：`oogiri-flow` Stage 1 发散段
> 唯一操纵变量：上下文边界
> 判定：预注册，先过硬门槛，再看主指标；平局有既定规则

---

## 0. 一句话

`oogiri-flow` 断言「三轨必须由三个独立子 Agent 产出，主 Agent 自己写三份等于没做」。这个断言可能是承重墙，也可能是仪式。
本实验只改一件事——**发散段是 3 个相互隔离的上下文，还是 1 个共享上下文**——其余全部对齐，然后用两级盲评 + 机械关卡判定它值不值得那两次额外调用。

---

## 1. 先拆变量：这个对比里其实有 5 件事

| # | 差异 | 臂 P（三轨并行） | 臂 S（单 Agent） | 本次处置 |
|---|---|---|---|---|
| 1 | **上下文隔离** | 3 个独立上下文，互不可见 | 1 个共享上下文，互相可见 | **唯一操纵** |
| 2 | **指令负荷** | 每次只背 1 套约束 | 一次背 3 套约束 | 无法分离，计入机制，报告注明 |
| 3 | **采样次数** | 3 次独立采样 | 1 次采样 | 对齐：总候选预算相同 |
| 4 | **候选预算** | 3 + N + 3 | 3 + N + 3 | 固定 N，两边完全一致 |
| 5 | **失败独立性** | 单轨挂掉可降级出结果 | 全有或全无 | 作为次要指标测 |

**必须承认的边界**：1、2、3 在物理上绑在一起。真正的「隔离」天然伴随「独立采样」和「更低的单次指令负荷」，无法只留下隔离而抽掉另外两个。
所以本实验能回答的是——**「三实例这条路」整体是否优于「单实例这条路」**，而不是「隔离的净因果效应」。
任何写成「隔离本身提升了 X」的结论都越界了。

---

## 2. 两个实验臂

### 2.1 臂 P（现行，对照组）

```
题目 → Stage 0（1 次）→ 3 个并发请求：sysA / sysB / sysC（各自独立上下文）
     → 合并候选池（带 [A轨]/[B轨]/[C轨] 前缀）→ Stage 2 公诉人 → 冠军
```

### 2.2 臂 S（候选，实验组）

```
题目 → Stage 0（同一次输出）→ 1 个请求：
       system = 三段轨道提示词原文顺序拼接（一字不改）
                + 一句"三条轨道互不参照、依次完成、各自独立成段"
                + JSON 输出契约
     → 同一合并池 → Stage 2 公诉人（同一提示词）→ 冠军
```

**关键**：两臂的轨道提示词必须逐字相同。差异只能来自"是谁在看这三段"。

### 2.3 为什么不是「单 Agent 连跑三轮」

那仍然是三个上下文（每轮新会话）或三次采样（同会话多轮），测的不是"一个脑子一次发散"。
若确实想拆开"隔离"与"多次采样"，那要加**第三臂**（同会话三轮），本版不做，预留。

### 2.4 对齐清单（任何一项没对齐，实验作废）

| 项 | 取值 |
|---|---|
| 模型 | 两边同一 model id，实验期间不换版本 |
| temperature | 两边同一值（生产默认 0.7） |
| max_tokens | 两边都不设（与生产一致，避免臂 S 被截断） |
| Stage 0 | 每题只跑一次，两臂共用同一份 JSON |
| 图片 | 同一编码、同一 base64 |
| 重试 | 同一套退避策略与次数 |
| Stage 2 | 同一提示词、同一模型、同一候选池格式 |
| 题面 | 同一份冻结文本 |

## 3. 样本：36 题，分层，冻结

| 层 | 数量 | 例子 |
|---|---|---|
| 具体物件题（文字） | 12 | 「停在三轮车上的共享单车」 |
| 抽象情绪/属性题（文字） | 12 | 「一个很努力但没用的人」 |
| 图像命题 | 12 | 真实上传图，含看得见的器物与姿态 |

- **来源**：线上真实提问 + 现有 benchmark 抽样。**禁止**用开发者自己刚想出来的题——会无意中偏向自己写的提示词。
- **排除**：题面 > 40 字、画面里找不出任何原生器物、纯谐音/纯文字游戏题。
- **冻结**：写入 `items.jsonl` 并记录 hash；实验期间不得增删改。改题 = 实验作废重来。

---

## 4. 运行协议

1. **交错执行**：同一题内，P 与 S 背靠背先后跑，避免模型版本/网络状况随时间漂移。
2. **臂序随机**：按 `hash(item_id, repeat)` 决定谁先，防止"后跑的有缓存优势"。
3. **重复 k=3**，每臂每题的 3 次独立采样。臂 S 内部 A/B/C 段落顺序轮换（ABC / BCA / CAB），抵消段落间的锚定。
4. **Stage 0 共用**：每题只解析一次题面，两臂复用。生产里每次都跑，但那是噪声源，不是被测对象。
5. **失败不静默**：请求失败记 `errors`，用同一 `run_id` 重跑覆盖；不允许拿失败的臂去和成功的臂比。
6. **冻结**：prompt hash、model id、日期、temperature、代码 commit 写进 `manifest.json`。

## 5. 测量：两层，主次分明

### 5.1 机械关卡（零主观，脚本判定）

逐条候选判定，不需要任何裁判：

- 长度 ≤ 14 字
- 零标点（中英文标点全表）
- 零空格
- 结构助词：`的 地 得 了 着 过`，**按词性判定**（jieba `u*` 词性才计），不做子串匹配
- 实词短语黑名单：`其实 原来 因为 所以`
- JSON 契约可解析、候选条数达标

输出：**合规通过率**。这是硬门槛，不是加分项。

**词汇关卡要做词性判定，不能做子串匹配**：首轮 pilot 用子串匹配，把「地砖」「地毯」「过路票」判成违规——`地` 和 `过` 是实词里的字，不是结构助词。这类误伤会同时扣两臂的分，把好好的实验拖进「实验无效」。改成 jieba 词性 `u*` 才计之后，两臂合规率才回到真实水平。

**动词关卡不进硬门槛**：提示词要求"必须含清晰具体动词"，但脚本判定只能靠分词。试行时 jieba 把「塞进」标成 `nr`（人名）、把「栓上」标成 `ng`，12 条全合规的短句里误报 2 条。
拿一把噪声这么大的尺子当 95% 硬门槛，会稳定地把两臂一起判死、白烧一轮预算。所以动词只做**诊断率**上报，人工抽查 20 条确认方向；真要当门槛，得先换成白名单动词表或一次 LLM 判定，那是另一笔成本。

### 5.2 盲评（两层，别混）

**层一 · 池级（看机制）**
- 多样性：池内两两字符 2-gram Jaccard 距离均值
- 轨道间重复：两条轨道冠军是否在讲同一个梗
- 命中率：池内是否有 ≥4 分候选

**层二 · 结果级（看用户拿到什么）**
- 两臂各跑一次 Stage 2，各得一个冠军
- 由**独立评估裁判**盲评这两个冠军：1–5 分

**选择裁判 ≠ 评估裁判**。Stage 2 会自己选出冠军，再让它给自己选的东西打分，必然偏。评估裁判必须是另一个模型、另一套提示词、看不到臂名。

### 5.3 盲评协议

- 两个冠军去标签、乱序、以「甲/乙」呈现
- 裁判不知道有两个实验臂，不知道这是实验
- 1–5 分标尺：
  - 5 = 0.5 秒「哈？」→ 0.5 秒爆笑，一读就懂
  - 4 = 好笑，但要多绕半秒
  - 3 = 看懂了，不笑
  - 2 = 勉强成立，语义暧昧
  - 1 = 不成立 / 看不懂 / 纯科普
- **两名不同模型家族的裁判**；排序不一致的样本由人工裁决
- 机器裁判只对 10 组人工盲评做校准；方向一致率 < 70% → 弃用机器结论，全人工

### 5.4 指标总表

| 级别 | 指标 | 用途 |
|---|---|---|
| **主** | Δ = mean(score_P − score_S)，5 分制 | 判定依据 |
| 主（辅） | P 胜 / 平 / S 胜 占 | 方向核对 |
| 次 | 池级多样性差、命中率差、轨道重复率 | 解释「为什么」 |
| 次 | 合规通过率、JSON 失败率、请求失败率 | 硬门槛 |
| 次 | 总 token、p50/p95 延迟、$/百题 | 平局规则 |
| 探索 | 文字/图像分层 Δ | 可能的分路设计 |

## 6. 分析

- **分析单位是题，不是次**：36 题 × 3 重复，按题做聚类 bootstrap（1 万次重采），不把 108 次当独立样本——同一题的 3 次高度相关。
- **主检验只有一个**：Δ 的 95% CI。其余全部标为探索性，不做显著性宣称。
- **中介检查**：若 Δ 显著，看多样性差是否同向。如果三轨赢了但多样性没差，说明赢得不是"三个脑子"，机制解释要另找（甚至可能是某一轨恰好强）。
- **分层**：文字/图像各自算 Δ，只在 CI 明确时才谈交互。

**样本量诚实说明**：36 题聚类后约能检出 **0.3–0.4 分**的真实差异（80% 把握）。比这更小的差异，本设计判不出来——按平局走。想检出 0.15 分要 150 题以上，不建议为这个问题付这个成本。

## 7. 验收标准（预注册，执行前不得改）

### 7.1 硬门槛（任一臂不过 → 该臂不具备可比资格）

| 编号 | 门槛 | 阈值 |
|---|---|---|
| G0 | 数据完整：每题每臂每重复都有可用池 | 缺失 ≤ 5% |
| G1 | 冠军合规率（长度/标点/空格/虚词，交付层，见 5.1） | ≥ 95% |
| G1d | 池合规率（同规则，诊断层） | 仅报告，不判死 |
| G2 | JSON 契约成功率 | ≥ 98% |
| G3 | 请求失败率 / p95 延迟 | ≤ 3% / ≤ 45s |
| G4 | 候选预算达标（B 轨条数 = 清单条数，"无" ≤ 30%） | 100% |

### 7.2 主判定

| 观察 | 判定 | 动作 |
|---|---|---|
| Δ ≥ +0.30 且 CI 下界 > 0 | 三轨并行胜 | 保留现状，把"必须三个独立实例"从主张升级为有证据的强制项，并附机制解释 |
| Δ ≤ −0.30 且 CI 上界 < 0 | 单 Agent 胜 | 改架构：三段视角、一次发散；同步改 SKILL 与 index.html |
| 其余（含 CI 跨 0） | 无实际差异 | 走 7.3 平局规则 |
| 任一臂没过 7.1 | 实验无效 | 修提示词/预算后整轮重跑，**不得**据此改架构 |

**为什么阈值是 0.3**：5 分制的半档，约等于"用户能稳定感知的差别下限"。低于它，赢了也说不清用户是否吃亏。

### 7.3 平局规则（按顺序，先触发先决）

1. 若单 Agent 在 G0/G3 上明显更差（失败率高一档或 p95 超 1.2 倍）→ **保留三轨**（可靠性优先）
2. 否则比总 token 成本 → **低者胜**（预期是单 Agent，约省 2 次调用的输入）
3. 再比维护面：3 套提示词 + 并发/重试/汇总代码 vs 1 套 → **单 Agent 胜**

> 默认方向：平局 → 切单 Agent。理由不是"单 Agent 更好"，而是"更便宜且一样好"。
> 现行架构是被告方，举证责任在它——它得证明自己值那两次调用。

### 7.4 可能的分支：图文交互

若图像题 Δ ≥ +0.3 而文字题 |Δ| < 0.3，说明"三个实例"的价值可能只在于**三次看图**。
此时不要笼统改架构，而是做分路：图像题走三轨，文字题走单 Agent。判定前必须再跑一轮确认，不能凭一次交互下结论。

### 7.5 什么结果会推翻「必须三个实例」

- 单 Agent 在冠军分上不输，合规率不输 → 该主张被证伪，SKILL 里"那一步等于没做"的措辞必须删掉。
- 三轨赢了，但多样性没赢 → 赢的不是隔离，机制解释要重写，不能拿这次结果给原主张背书。

## 8. 威胁与对策

| 威胁 | 影响 | 对策 |
|---|---|---|
| 臂 S 一次背三段，输出被截断 | 假性变差 | 两边都不设 max_tokens；检查完成率 |
| 臂 S 段落顺序锚定 | 后段被前段带跑 | 跨重复轮换 ABC/BCA/CAB |
| 选择裁判与评估裁判同源 | 自夸偏差 | 评估裁判换模型家族；两次独立盲评 |
| 裁判偏爱长句/网络梗 | 系统性偏移 | 全部 ≤14 字且封禁网梗；两名裁判交叉 |
| 题目由开发者自拟 | 偏向自己写的提示词 | 只用真实提问与既有 benchmark |
| 108 次当独立样本 | CI 过窄，假阳性 | 按题聚类 bootstrap |
| 模型版本漂移 | 两臂不在同一状态 | 同日交错执行，记录 model 返回字段 |
| 多重比较 | 挑出"显著"的分层 | 只做 1 次主检验，其余标探索性 |
| Stage 2 重写洗掉池差异 | 结果级看不出差别 | 池级指标并行报告，别只看冠军 |

- `report.md`：硬门槛表 + Δ 与 CI + 分层 + 多样性 + 成本 + 一句话结论

## 附录 A：臂 S 提示词拼装规范

```
【本次任务：三轨并行发散，一次完成】
你将依次完成三条轨道的发散。每条轨道只产出该轨道的候选，三条轨道互不参照、互不借用对方的词，不得合并成一种口吻。
全部完成后再输出，顺序如下。

=== 轨道 1 / 体面破绽 ===
<Subagent A 提示词原文，逐字不改>

=== 轨道 2 / 异业动作 ===
<Subagent B 提示词原文，逐字不改>

=== 轨道 3 / 物理死磕 ===
<Subagent C 提示词原文，逐字不改>

【输出契约】只输出合法 JSON，除 JSON 外无任何字符：
{"A": ["...", "...", "..."],
 "B": [{"category": "[序号] 类别名", "punchline": "..."}],
 "C": ["...", "...", "..."]}
```

注意「互不参照」是**指令**，不是保证——单 Agent 能不能真的不串味，正是被测的东西。
